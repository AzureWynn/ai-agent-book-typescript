# 精简论文：渐进式披露式 Agent Skills 对上下文效率的影响

## 摘要

随着大语言模型（LLM）在 Agent 中的广泛应用，如何在有限的上下文窗口内让 Agent 获得专业领域能力，成为影响效率与成本的关键问题。本文提出一种基于 **渐进式披露（Progressive Disclosure）** 的 Agent Skills 机制：系统提示词中只注入各 Skill 的元数据（名称与描述），Agent 在任务需要时才按层加载 Skill 的完整流程、子文档与捆绑脚本。实验表明，该方法能在不牺牲任务完成质量的前提下，显著降低基线上下文占用，并让能力按需、按层、可审计地扩展。

## 1 背景与动机

传统的做法是把所有工具说明、领域知识一次性写入系统提示词。随着 Skill 数量增长，提示词迅速膨胀，带来三个问题：token 成本上升、指令间相互干扰导致遵循率下降、以及维护困难。渐进式披露把「知识」从系统提示词中移出，放进按需加载的 Skill 文件。

## 2 方法：三层渐进式披露

### 2.1 第一层：元数据
Agent 启动时，系统提示词只包含每个 Skill 的 `name` 与 `description`（约数百 token）。此时 Agent 知道"有哪些能力"，但不知道"怎么做"。

### 2.2 第二层：核心流程
当任务命中某 Skill 时，Agent 通过工具加载该 Skill 的 `SKILL.md`，获得完整的执行流程与脚本调用约定。

### 2.3 第三层：细则与脚本
实现细节、版式/配色等技术说明存放在 `reference.md` 等子文档；可执行脚本作为捆绑资源，由 Agent 按需调用。

## 3 实验

以"从论文生成 PowerPoint"为任务验证该机制。基线方案把生成规则全部写入系统提示词；实验方案采用三层渐进式披露。对比指标包括：启动时上下文 token 数、任务完成率、生成文件有效性（能否被 python-pptx 重新打开）。

## 4 结果与讨论

实验方案在启动时上下文占用仅为基线方案的约 10%，而任务完成率与生成文件有效性基本持平。渐进式披露还带来额外收益：Skill 独立成文件、便于复用与审计，且新增能力无需改动主程序。

## 5 结论

渐进式披露式 Agent Skills 是平衡上下文效率与能力扩展的有效设计。它把「能力清单」与「能力实现」解耦，让 Agent 像使用工具书一样按需查阅，值得作为 Agent 系统的默认能力组织方式。
