# Agent Skills 渐进式披露 —— 教学笔记

> 本笔记对应实验 2-6（渐进式披露式 Agent Skills）。
> 核心目标：**理解"为什么 Agent 不该把所有知识一次性塞进系统提示词"。**

---

## 一、这个实验在干什么？

一句话：**用"按需加载"代替"全部塞入"，让 Agent 既能干复杂活，又不被提示词撑爆。**

```
❌ 传统做法：把所有技能说明一次性写进系统提示词
   系统提示词：[技能1全文][技能2全文][技能3全文]... → 太长了！

✅ 渐进式披露：先给目录，需要时才加载
   系统提示词：[技能名1][技能名2][技能名3] → 很短！
   需要时：read_skill("pptx") → 加载流程
   需要时：read_skill_file("pptx") → 加载细则
```

就像你入职时，公司只给你一份**部门通讯录**，而不是一本**全员操作手册**。需要做 PPT 时，你才去查"PPT 制作流程"，查完就忘，不需要时完全不占脑子。

### 每层详解

#### 第一层：元数据（薄目录）

**系统提示里只有这些（~200 token）：**
```
== 已安装的 Skills（薄目录，仅元数据）==
- pptx: 从论文或大纲生成 PowerPoint（.pptx）演示文稿。
         Use when 用户要求生成 PPT / 演示文稿。
```

**Agent 知道什么？** 只知道"有一个叫 pptx 的技能，能生成 PPT"。不知道怎么做。

#### 第二层：核心流程

**Agent 判断需要做 PPT 后，调用 `read_skill("pptx")`（~1000 token）：**
```
# pptx SKILL.md
## 目标
根据论文/大纲内容，规划一份 8-12 页的幻灯片，生成真实可打开的 .pptx 文件。

## 工作流程
1. 读输入 → 理解结构
2. 规划大纲 → 按 schema 组织幻灯片
3. 执行生成 → 调用 run_skill_script
4. 校验 → python-pptx 重新打开验证
```

**Agent 知道什么？** 知道了完整流程：先读论文，再规划大纲，再调用脚本生成。

#### 第三层：细则与脚本

**需要细节时，调用 `read_skill_file("pptx", "reference.md")`（~700 token）：**
```json
大纲 schema：
{
  "title": "字符串",
  "slides": [{"title": "字符串", "bullets": ["短语1"...]}]
}
注意：outline 总长度 ≤1000 字符，bullets 用短短语。
```

**Agent 知道什么？** 知道了具体参数约束。

### 可视化对比：一次性 vs 渐进式

```
一次性塞入（传统）：
┌──────────────────────────────────────────────────┐
│  系统提示词（每次对话都发送）：                      │
│  ┌──────────────────────────────────────────────┐ │
│  │ 技能1全文 (~1000 token)                       │ │
│  │ 技能2全文 (~1000 token)                       │ │
│  │ 技能3全文 (~1000 token)                       │ │
│  │ ... × 20 个技能 = ~20,000 token               │ │
│  ├──────────────────────────────────────────────┤ │
│  │ 对话内容（可能只有 1,000 token）               │ │
│  └──────────────────────────────────────────────┘ │
│                                                    │
│  问题：20K token 的提示词，只为了 1K token 的对话   │
└──────────────────────────────────────────────────┘

渐进式披露（本实验）：
┌──────────────────────────────────────────────────┐
│  系统提示词（每次对话都发送）：                      │
│  ┌──────────────────────────────────────────────┐ │
│  │ 技能1元数据 (~100 token)                       │ │
│  │ 技能2元数据 (~100 token)                       │ │
│  │ ... × 20 个技能 = ~2,000 token               │ │
│  ├──────────────────────────────────────────────┤ │
│  │ 对话内容（可能只有 1,000 token）               │ │
│  └──────────────────────────────────────────────┘ │
│                                                    │
│  需要时额外加载：                                    │
│  → read_skill("pptx")    +1000 token（一次性）     │
│  → read_skill_file(...)   +700 token（一次性）     │
│                                                    │
│  不需要时：不发送，不占上下文                        │
└──────────────────────────────────────────────────┘
```

## 三、为什么这很重要？

### 视觉化：三个问题

```
问题一：上下文窗口有限
┌──────────────────────────────────┐
│  LLM 上下文窗口 = 128K token     │
│                                  │
│  塞 20 个技能：                   │
│  ┌──────────┐ ┌──────────┐      │
│  │ 技能知识  │ │ 技能知识  │      │
│  │ 20K token│ │          │      │
│  ├──────────┤ ├──────────┤      │
│  │ 对话内容  │ │ 对话内容  │      │
│  │ 8K token │ │          │      │
│  └──────────┘ └──────────┘      │
│  剩余可用：78K token             │
│                                  │
│  渐进式披露后：                   │
│  ┌──────────┐ ┌──────────┐      │
│  │ 技能元数据│ │ 对话内容  │      │
│  │ 2K token │ │ 8K token │      │
│  ├──────────┤ ├──────────┤      │
│  │           │ │ 剩余：   │      │
│  │           │ │ 118K token│     │
│  └──────────┘ └──────────┘      │
└──────────────────────────────────┘

问题二：注意力稀释
┌──────────────────────────────────┐
│  提示词越长，模型越容易"忘前文"    │
│                                  │
│  500 页手册 → 员工只记得标题       │
│  5000 页手册 → 员工什么都记不住    │
│                                  │
│  渐进式披露 = 一次只看一页         │
└──────────────────────────────────┘

问题三：成本
┌──────────────────────────────────┐
│  每次对话都要发送完整 system prompt│
│                                  │
│  一次性：  20K token × 每次对话   │
│  渐进式：  2K token × 每次对话    │
│           + 1.7K token（按需）    │
│                                  │
│  省 ~90% 的 system prompt 成本   │
└──────────────────────────────────┘
```

## 五、核心结论

```
┌─────────────────────────────────────────────────┐
│              渐进式披露的四大优势                   │
├─────────────────────────────────────────────────┤
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐      │
│  │ 按需加载  │  │ 注意力聚焦│  │ 成本可控  │      │
│  │          │  │          │  │          │      │
│  │ 不需要时 │  │ 模型只看到│  │ 只在需要 │  │
│  │ 不占空间 │  │ 当前相关 │  │ 时消耗   │  │
│  │          │  │ 的信息   │  │ 额外token│  │
│  └──────────┘  └──────────┘  └──────────┘      │
│                                                  │
│       ┌──────────┐                                │
│       │ 可扩展   │                                │
│       │          │                                │
│       │ 加新技能 │                                │
│       │ 只加文件 │                                │
│       │ 不改提示 │                                │
│       └──────────┘                                │
│                                                  │
└─────────────────────────────────────────────────┘
```

| # | 结论 | 一句话 |
|---|------|--------|
| 1 | **按需加载** | 不需要的知识不占上下文 |
| 2 | **注意力聚焦** | 模型只看到当前任务相关的信息 |
| 3 | **成本可控** | 只在需要时消耗额外 token |
| 4 | **可扩展** | 加新技能只需加一个 SKILL.md，不改系统提示词 |

## 六、延伸思考

```
和传统 Prompt Engineering 的对比：

┌─────────────────┐  ┌─────────────────┐
│  传统做法        │  │  渐进式披露      │
├─────────────────┤  ├─────────────────┤
│ 所有知识写进     │  │ 只写目录         │
│ system prompt    │  │                  │
│                  │  │ 需要时读文件     │
│ 修改要改提示词   │  │ 加文件就行       │
│                  │  │                  │
│ 适合：技能很少   │  │ 适合：技能很多   │
│                  │  │                  │
│ 系统提示词膨胀   │  │ 上下文可控       │
└─────────────────┘  └─────────────────┘
```

1. **和传统 Prompt Engineering 的关系？**
   - 传统：把所有规则写进 system prompt
   - 渐进式披露：先给目录，需要时才加载
   - 两者不是互斥的——渐进式披露是一种**架构选择**

2. **什么时候不适合渐进式披露？**
   - 技能很少且总是一起用（如只有 1-2 个技能）
   - 每次任务都需要所有技能
   - 加载延迟不可接受

3. **实际应用？**
   - Anthropic 的 Agent Skills 规范就是基于这个思想
   - Claude 的 Skills 系统：`~/.claude/skills/` 下每个 skill 一个目录，frontmatter 是薄目录，内容按需加载
   - 本质：**把"知识"从"提示词"变成"文件系统"**

## 八、快速验证清单

```bash
# 1. 安装依赖（Python + python-pptx）
npm run setup

# 2. 在线模式（真实模型驱动）
npm run run
# 输出：read_skill → run_skill_script → output.pptx

# 3. 离线模式（确定性演示，无模型）
npm run offline
# 输出：同样的工具通道，确定性生成

# 4. 换论文生成
npm run run -- --paper 你的论文.md -o output/deck.pptx
```

**看完输出问自己：模型启动时知道怎么做 PPT 吗？它是怎么学会的？**

答案在渐进式披露的三层加载里：
- 启动时只知道"有 pptx 这个技能"（第一层）
- 调用 `read_skill` 后才知道流程（第二层）
- 调用 `read_skill_file` 后才知道具体参数（第三层）
- 一步步加载，一步步学会
