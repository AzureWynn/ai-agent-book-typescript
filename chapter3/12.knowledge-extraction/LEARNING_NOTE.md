# Chapter 3-12：隐性知识提取 · 学习笔记（大白话版）

> 本笔记所有刑期数字均来自合成数据的原型统计，仅用于教学演示因子聚类方法，不构成法律意见。

## 一、这个实验在干什么？

一句话：**别只把知识库当仓库查，要把它读懂，归纳出能断事的经验。**

```
传统做法：判例存着 → 问的时候搜出来 → 贴给模型看
本实验：  判例存着 → 读出影响判决的因素 → 按因素聚出典型案件
       → 新案先匹配"像哪类"，再按同类历史区间给建议
```

四段流水线（21 条合成判例，盗窃/伤害/诈骗 × 7）：

```
判例文本 ──①因子发现──▶ schema（核心4 + 各罪名扩展）
              ②结构化抽取（照 schema 逐条抽）
              ③各罪名内聚类（KMeans，k 由轮廓系数选）
              ④对话建议（缺什么问什么，匹配最近原型）
```

## 二、因子为什么不预设？

预设 schema 的问题：你列不全。让数据自己说话：

```
规则版（默认离线）：关键词扫描自由归纳 → 归并成 core + extensions
  core：自首 / 赔偿 / 认罪认罚 / 前科
  盗窃扩展：金额 / 团伙 / 持械 / 入户
  伤害扩展：等级 / 预谋 / 持械
  诈骗扩展：金额 / 受害人数 / 团伙

LLM 版（--llm-discover，gemma4）：
  同一批案情自由列因素 → 与规则版对比
  实测：11/11 全覆盖，一条不落
```

生产用 LLM，教学用规则——两边对得上，说明规则版是合格的代理。

## 三、抽取为什么是 100%？

`npm run eval` 第一行：抽取准确率 154/154 = 1.000。

别误会：这不是"模型很强"，而是**生成与抽取用了同一套线索**——因子写进案情时用"自首"，抽取时也找"自首"。官方也一样（已知公式加噪声生成，再读回来）。这个数字验证的是抽取器实现正确，不是发现质量。发现质量看覆盖度（上一节）。

## 四、聚类在干什么？

把因子翻译成数字，再按罪名聚：

```
分类因子（伤害等级）→ one-hot，不用 1/2/3（避免暗示轻重顺序）
金额/人数 → 取 ln 压量纲（12万和8千差15倍，ln 后只差2.7）
是非情节 → 0/1
全部再标准化（z-score），KMeans，k=2~3 按轮廓系数选
```

实测三个罪名都选了 k=3，轮廓系数 0.286 / 0.064 / 0.342——伤害罪的 0.064 很弱，7 个样本本来就撑不起强聚类，诚实记录。

聚出来的原型长这样（诈骗罪）：

```
fraud#2 n=3 中位15月 [14~17]：小额、少人、无加重要素 —— "轻案"型
fraud#0 n=2 中位47月 [40~55]：赔偿、自首 —— "配合型"
fraud#1 n=2 中位75月 [71~80]：团伙、高额、多人 —— "重案"型
```

## 五、重要性分两层

```
全局重要性：某因子在所有原型之间有多"分得开"（簇间方差占比）
  → 决定追问顺序：缺一堆信息时先问哪个

原型内定义性因子：某原型相对平均最突出的因子（z 分数）
  → 解释"这类案为什么判这个数"：持械预谋重伤型 z=+3.9
```

小样本下二值因子常被完美分开，重要性大量饱和到 1.00——看排序和追问行为即可，别迷信小数点后两位。

## 六、对话建议怎么工作？

```
User：朋友偷了辆电动车
Agent：识别盗窃罪，已知[无] → 按全局重要性追问"赔偿"
User：偷电动车价值8000元，自首并赔偿
Agent：匹配 theft#0（中位12月，区间12~12月，距离0.00）
       还缺"前科"（重要性首位）→ 请补充
```
（以上"12月"等数字均为合成原型统计，演示匹配机制用，不是对真实案件的量刑。）

三条铁律：
1. 缺什么按重要性问，不按固定顺序
2. 匹配只看已知维度，未知的不参与距离
3. 所有刑期数字来自原型统计，模型只负责讲清楚 + 必须带免责声明

## 七、覆盖率 19/21 是什么意思？

留一法式的自查：每条判例用自己的全部已知因子匹配原型，看刑期落不落在该原型区间内。19/21 落中，2 条匹配到了邻居原型。

注意这是**乐观估计**（原型就是用这些案子建的）。真验收要留出法（held-out），官方 campaign 就是这么做的。教学里知道"自查≠验收"就够了。

## 八、本实验怎么跑

```bash
npm run demo      # 发现→抽取→聚类→对话，全流程追踪
npm run eval      # 抽取准确率 + 原型表 + 自查覆盖率
npx tsx src/main.ts --mode discover            # 规则发现 schema
npx tsx src/main.ts --mode discover --llm-discover  # gemma4 自由归纳对比（需 Ollama）
npm run answer    # gemma4 把结构化结论讲成人话（需 Ollama）
```

## 九、关键洞察

1. **因子不预设**——让数据自己列，LLM 版 11/11 复现规则版
2. **抽取 100% 是自洽性检查**——生成与抽取同源，别当成 discovered truth
3. **分类因子 one-hot**——数字编码不能偷渡顺序假设
4. **k 让轮廓系数选**——别拍脑袋，7 样本选 k=3 也有 0.064 的弱聚类，诚实记录
5. **刑期数字只出来源统计**——模型负责解释，不负责发明

## 十、常见问题

- **轮廓系数很低**：样本太少（每罪名 7 条）时正常；看原型是否可解释
- **重要性全是 1.00**：小样本+二值因子的饱和 artifact；看排序
- **覆盖率不是 100%**：有 2 条匹配到邻居原型；换留出法会更低，这是对的
- **否定句会误抽**："无前科"含"前科"二字——规则抽取处理不了否定，语料里已避开，生产用 LLM 抽取
- **任何输出都不是法律意见**：合成数据、简化因子、玩具聚类——三重简化，仅演示范式
