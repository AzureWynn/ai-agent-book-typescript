# Chapter 3-6：混合检索流水线 · 学习笔记（大白话版）

## 一、这个实验在干什么？

一句话：**把稀疏检索和稠密检索拼成一条流水线，再排一次序。**

3-4 学了稠密检索（懂意思，但可能把相近编码搞混）；3-5 学了 BM25（认词准，但不懂同义词）。3-6 把它们串起来：

```
查询
 ├─→ BM25（稀疏）  → 候选 + 分数
 ├─→ Embedding（稠密）→ 候选 + 分数
 ├─→ 融合（RRF / 加权）→ 合并后的候选排序
 └─→ 重排（rerank）    → 最终 top-k
```

## 二、为什么需要四个阶段？

每个阶段只解决一个问题：

```
召回（recall）  ← 稀疏 + 稠密各取一批候选
  │ 目标：相关文档至少进入候选集
  ▼
融合（fusion）  ← 两路排名合并成一个
  │ 目标：两路都认可的文档排前面
  ▼
重排（rerank）  ← 对候选逐个细看再排序
  │ 目标：把最好的推到第 1 位
  ▼
最终 top-k
```

关键约束：**重排只能给候选重排序，找不回漏掉的文档**。所以先看召回，再看排序——候选集里没有，再强的重排也没用。

## 三、融合的两种做法

### RRF（倒数排名融合）

只看排名，不看原始分数：

```
score(d) = Σ 1 / (k + rank)，k=60
```

文档在某路排第 1，贡献 `1/61`；排第 10，贡献 `1/70`。两路分数加起来就是融合分。

为什么用排名而不用原始分？BM25 的分（几分到几十分）和余弦相似度（0~1）量纲完全不同，直接相加会被一路主导。排名是无量纲的，两路天然可比。

### 加权融合

先把两路分数各自 min-max 归一到 `[0,1]`，再加权求和：

```
combined = w_dense × norm(dense) + w_sparse × norm(sparse)
```

缺席某路的文档，该路按 0 算。权重默认各 0.5，可调。

## 四、重排是什么？

重排是对候选集做第二次、更贵的精排。生产里常用 cross-encoder（把"查询+文档"一起喂给 Transformer 打分）。本实验用一个**可解释的特征重排**代替，保证离线可跑、每一步都看得懂：

```
rerank分 = 1/(融合排名+1) + 0.5×整句命中 + 0.5×查询词覆盖率
```

- 融合排名越前，基础分越高
- 查询整句原样出现在文档里，加 0.5（精确匹配奖励）
- 查询词被文档覆盖得越多，加得越多

注意：整句匹配用的是**词边界匹配**，不是子串包含——否则查 `cat` 会误中 `replicate` 里的 `cat`。这是一个真实踩过的坑。

## 五、互补是怎么发生的？

两个真实追踪：

```
查询 "cat"：
  BM25：无候选（词面零交集，kitten/feline 里没有 cat）
  Dense：kitten #1，feline #2（语义认识）
  Hybrid-RRF：kitten #1，feline #2（稠密把路补上了）

查询 "XR-7003"：
  BM25：xr_7003 #1（编码精确命中）
  Dense：xr_7003 #1，但 xr_7001/xr_7002 紧随其后（兄弟编码向量很近）
  Hybrid-RRF：xr_7003 #1（两路一致，位置更稳）
```

## 六、怎么读评测表？

`npm run eval` 实测（14 篇语料，7 查询，top-3）：

```
BM25 (sparse)      recall=0.7857
Dense              recall=1.0000
Hybrid-RRF         recall=1.0000
Hybrid-Weighted    recall=1.0000
Hybrid-RRF+Rerank  recall=1.0000
```

读法：
- BM25 的 0.7857 来自 `cat`（0/2）和 `kitty behavior`（只找回 feline，1/2）——词面匹配的边界
- 稠密在这组小语料上全对，不代表稠密永远赢；换近似编码、换更大的库，稠密也会混淆
- 混合等于稠密在这里，但它多了一层保险：两路同时认可的结果更稳
- 重排在这里没改变召回（候选已满分）——重排的价值在更大的候选池和更难的查询上体现

## 七、本实验怎么跑

```bash
npm run demo    # XR-7003 追踪 + kitty behavior 追踪（--query 可换）
npm run eval    # 7 查询 × 5 阶段的 recall/MRR/nDCG 表
```

常用开关（和官方 evaluate.py 对齐）：

```bash
npx tsx src/main.ts --mode eval --no-dense    # 纯 BM25 基线
npx tsx src/main.ts --mode eval --no-rerank   # 关重排，看融合本身
npx tsx src/main.ts --mode demo --fusion weighted --query "HTTP-403"
```

## 八、参数怎么调

| 参数 | 作用 |
|------|------|
| `--fusion rrf\|weighted` | 融合方法，默认 rrf |
| `RRF_K=60` | RRF 阻尼，越大越不区分排名先后 |
| `DENSE_WEIGHT / SPARSE_WEIGHT` | 加权融合两路权重 |
| `CANDIDATE_POOL=20` | 每路候选数，越大重排越贵 |
| `BM25_K1 / BM25_B` | 稀疏路 BM25 参数（见 3-5） |

## 九、关键洞察

1. **先召回、后排序**——候选集漏了，重排救不回来
2. **RRF 用排名而不用原始分**——解决两路量纲不同的问题
3. **混合的价值是鲁棒性**——不是每组数据都拉开差距，但两路互补后下限更高
4. **重排只重排候选**——它的上限是候选集的质量
5. **词边界是细节也是正确性**——子串匹配会让 `cat` 命中 `replicate`，教学代码里修过一次

## 十、常见问题

- **Ollama 没启动**：稠密路需要 `ollama serve` + `nomic-embed-text`；只想看 BM25 用 `--no-dense`
- **评测全满分**：语料小（14 篇）时正常；看逐查询追踪比看平均数更有信息
- **重排没变化**：候选已经排好时正常；重排价值在候选池更大、查询更难时体现
- **想换融合方法**：`--fusion weighted`，注意加权对分数尺度敏感
- **生产用什么重排**：cross-encoder（如 bge-reranker）；本实验的特征重排是教学替代品
