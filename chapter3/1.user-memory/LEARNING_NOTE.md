# Chapter 3-1：用户记忆系统 · 学习笔记（大白话版）

## 一、这个实验在干什么？

一句话：**让 Agent 记住用户，跨对话也能记得。**

想象一个客服场景：用户第一次说"我喜欢吃火锅"，Agent 记住了。第二次用户说"帮我推荐附近的餐厅"，Agent 应该想到"哦，他喜欢火锅，推荐火锅附近的餐厅"。

如果没有记忆，每次对话都是全新的，Agent 什么都不记得。

## 二、为什么需要这个？

```
没有记忆：
  对话1：用户说"我喜欢吃火锅"  → Agent 忘了
  对话2：用户说"推荐餐厅"      → Agent 不知道用户喜欢什么

有记忆：
  对话1：用户说"我喜欢吃火锅"  → Agent 存入记忆
  对话2：用户说"推荐餐厅"      → Agent 读取记忆 → 推荐火锅
```

**大白话：记忆就是 Agent 的"脑子"。**

## 三、核心架构：对话 vs 后台分离

这是本实验最重要的设计思想：

```
┌─────────────────────────────────────────────┐
│            对话 Agent（只读）                  │
│                                             │
│  用户："我喜欢吃火锅"                         │
│  → 读取现有记忆                              │
│  → 拼入提示词                               │
│  → 回复用户                                  │
│  → 不修改记忆                               │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│          后台处理器（只写）                    │
│                                             │
│  每 N 轮对话后自动触发                         │
│  → 分析最近对话                              │
│  → 提取重要信息                              │
│  → 写入记忆文件                               │
└─────────────────────────────────────────────┘
```

**为什么分离？**

- **对话 Agent** 像"前台服务员"：只负责接待客户，不能随便翻档案柜
- **后台处理器** 像"档案管理员"：专门负责归档，平时不打扰
- 这样做的好处：
  1. 对话响应快（不需要写文件）
  2. 不会漏写记忆（后台专门负责）
  3. 避免 KV Cache 失效（不修改 system prompt）

## 四、4 种记忆模式（从简单到复杂）

| 模式 | 结构 | 适合场景 | 类比 |
|------|------|----------|------|
| `notes` | 简单列表 | 基本事实 | 便签纸 |
| `enhanced_notes` | 完整段落 | 完整上下文 | 备忘录 |
| `json_cards` | 层级 JSON | 结构化数据 | 表格 |
| `advanced_json_cards` | 完整卡片（含 backstory） | 完整档案 | 档案袋 |

```
notes 示例：
  - 用户喜欢火锅

enhanced_notes 示例：
  用户 Alice 在 TechCorp 担任高级工程师，
  喜欢吃火锅，住在北京朝阳区。

json_cards 示例：
  {category: "personal", key: "food", value: "火锅"}

advanced_json_cards 示例：
  {
    category: "personal",
    cardKey: "food_preference",
    card: {
      backstory: "用户首次对话时提到喜欢火锅",
      person: "Alice",
      relationship: "primary account holder",
      preference: "火锅"
    }
  }
```

## 五、React 循环 + 工具调用

Agent 使用**工具调用**来操作记忆：

```
用户说："我刚换了新工作"
       ↓
Agent 思考："这条信息需要记住"
       ↓
调用工具：add_memory(content="用户换了新工作")
       ↓
记忆系统写入文件
       ↓
Agent 回复："好的，记住你了！"
```

**4 个工具：**

| 工具名 | 干什么 | 什么时候用 |
|--------|--------|-----------|
| `add_memory` | 存新记忆 | 发现新信息时 |
| `update_memory` | 改旧记忆 | 信息变化时 |
| `delete_memory` | 删记忆 | 信息过时了 |
| `search_memories` | 搜记忆 | 需要回忆时 |

## 六、大白话总结

```
整体流程：

  对话阶段：
  ┌─ 用户说话
  ├─ Agent 读取记忆（只读，不改）
  ├─ 拼入提示词
  └─ 回复用户（快速，不写文件）

  后台阶段（每 N 轮）：
  ┌─ 读取最近的对话历史
  ├─ 分析哪些信息需要记住
  ├─ 调用工具写入记忆
  └─ 持久化到 JSON 文件

  下次对话时：
  ┌─ 读取更新后的记忆文件
  └─ 已有新记忆可以参考
```

## 十、关键结论

1. **对话和记忆必须分离** — 否则每次对话都改文件，KV Cache 全失效
2. **4 种模式逐步增强** — 从便签到档案袋，按需选择
3. **工具调用是核心机制** — Agent 通过 `add_memory`/`update_memory` 等工具操作记忆
4. **不修改 system prompt** — 这是贯穿全书的核心原则（KV Cache + Chat Template）
