# Chapter 3-9：Agentic RAG 用户记忆 · 学习笔记（大白话版）

## 一、这个实验在干什么？

一句话：**把 3-8 的多轮取证，用在用户跨会话的对话历史上。**

用户说"按我上次的偏好安排吧"，偏好散落在好几次对话里：本田保养计划在 s1，特斯拉胎压在 s2，保养确认在 s6。一次检索找不全，Agent 要分几轮补齐——和 3-8 一样的缺口驱动循环，换了个知识库：

```
3-8：法条库（静态文档）
3-9：对话记忆库（16 轮对话 → 8 个会话分块）
```

## 二、分块是怎么切的？

长对话不能整段入库，按**会话**切块，上一会话末轮带上做重叠：

```
k_s1 = [s1 两轮]                          要素：本田里程、保养计划
k_s2 = [s1 末轮(重叠) + s2 两轮]           要素：特斯拉胎压
k_s3 = [s2 末轮(重叠) + s3 两轮]           ……
```

每块带 enrichment 头：`[session s2 | rounds 3,4 (overlap)]`。重叠防止边界丢失：万一关键信息恰好在会话交界处，不会因为切一刀就失联。

## 三、三个记忆工具

| 工具 | 作用 | 什么时候用 |
|------|------|-----------|
| `search_memory` | 按查询搜分块 | 每轮必调 |
| `get_conversation_context` | 看命中块的前后邻居 | 首轮命中后展开一次 |
| `get_full_conversation` | 读某会话全部原文 | 收尾前读一次，答题前看全 |

实测追踪里三个都会出现，`tools=4` 的典型构成：2 次 search + 1 次 context + 1 次 full。

## 四、缺口驱动选 follow-up

和 3-8 的区别：follow-up 不是按固定顺序取，而是**看当前缺什么选什么**：

```
round 1 查"哪辆车先去保养" → 缺 [特斯拉胎压]
候选 follow-up 里谁覆盖"特斯拉胎压"？→ "特斯拉检查" → 就它了
round 2 查"特斯拉检查" → 缺口补完 → 停
```

生产里这一步由模型现场写查询；教学里用"缺口覆盖度最大"代替，机制一样：**查询选择由缺口决定**。

## 五、过期记忆怎么办？

用户先说喜欢海边（s3），后来取消改去山区（s4）。系统应该：

```
保留 s3（历史事实：曾经喜欢海边）
保留 s4（最新事实：取消了）
回答"还去吗"时以 s4 为准
```

检索层把新旧都召回（`海边旅行还去吗` → [k_s3, k_s4, ...]），**新旧裁决交给作答层**：prompt 里写"以后来记录为准"，gemma4 会选 s4。这就是"保留记忆、回答取新"。

## 六、实测怎么读？

`npm run eval`（8 会话分块，5 问题，top-3）：

```
L1 ×2   naive=100%  agentic=100%  检索 1→1
L2 车辆 naive=67%   agentic=100%  检索 1→2（补特斯拉那块）
L2 海边 naive=100%  agentic=100%  检索 1→1
L3 出门 naive=50%   agentic=100%  检索 1→2
```

读法：
- L1 打平：单要素问题不需要 Agent
- 差距集中在跨会话问题：要素散在不同会话，一次检索预算不够
- 海边题打平但有价值：新旧记忆都被召回，考的是作答层取新，不是检索层
- 总表：0.83 → 1.00

## 七、本实验怎么跑

```bash
npm run demo      # L2 车辆追踪 + L2 海边追踪
npm run eval      # 5 问题 × 单次/多轮的证据召回表
npm run answer    # 多轮取证 → 读全会话 → gemma4 作答（需 Ollama）
```

换查询（无标注时只展示单次检索）：

```bash
npx tsx src/main.ts --mode demo --query "特斯拉胎压怎么办"
npx tsx src/main.ts --mode answer --query "哪辆车先去保养"
```

## 九、关键洞察

1. **3-9 = 3-1 的记忆 × 3-8 的取证**——记忆库换成对话历史，检索换成多轮
2. **分块是检索的前置**——怎么切决定什么能被召回，会话是天然边界
3. **follow-up 选择也是决策**——看缺口选查询，比固定顺序少一轮（本实验 3 轮→2 轮）
4. **过期不删除**——保留历史、作答取新；删除是 3-1 记忆管理的另一课
5. **工具分工**：search 找线索，context 看邻居，full 读原文——由粗到细

## 十、常见问题

- **多轮只多一轮**：语料小（8 块）时正常；看"缺口如何被补上"比看轮数重要
- **海边题打平**：正常，它考的是作答层取新，不是检索层；去 `answer` 模式看效果
- **overlap 会不会泄题**：会帮单次检索一点忙，但跨会话缺口依然存在（车辆题 67% 证明）
- **自定义查询无分解**：无标注缺口信息，只能单次检索；玩多轮需先标 facets 和 subqueries
- **生产记忆库更大**：分块数千时，BM25 换混合检索（3-6）、 embedding 换向量（3-4），循环机制不变
