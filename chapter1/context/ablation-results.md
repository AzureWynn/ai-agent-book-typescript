# 消融实验结果报告（Ablation Study）

> 本文档记录一次实际运行的结果（模型：`gemma4:latest`，温度 0，最大迭代 10）。

## 实验说明

通过逐项移除 Agent 的上下文能力，量化各模块（历史记录、推理、工具调用、工具结果）对任务完成效果的影响。

### 实验任务

请分析以下财务数据：某公司2024年Q1营收为1500万美元，Q2营收为1800万美元。

1. 计算同比增长率（假设去年同期Q1为1200万美元）；
2. 将Q2营收转换为人民币（使用汇率工具）；
3. 计算两个季度的总营收（以人民币计）。

### 结果判定标准（三个独立维度）

- **完成（completed）**：是否有终止回复（`finalAnswer` 非空）。≠ 答对。
- **结局（outcome）**：合并 `completed` + 数值规则 + 数字依据后的标签：
  - `✓ 答对`：通过任务专属数值规则（rubric）
  - `✗ 答错`：有终止回复但数值规则不通过
  - `⚠ 编造数字`：答案含任务与观察之外凭空出现的数字
- **数字依据（grounding）**：答案里的大额数字是否来自任务文本或模型真正看到的工具观察。
  - `已看工具`：模型看到了真实观察（此时正确性完全交给 rubric 裁决）
  - `UNSUPPORTED`：无观察却给出任务之外的数字

## 结果汇总

| 模式 | 迭代次数 | 工具调用 | 完成 | 结局 | 数字依据 | 耗时(ms) |
| --- | ---: | ---: | --- | --- | --- | ---: |
| full | 5 | 4 | true | ✓ 答对 | 已看工具 | 76280 |
| no_history | 2 | 1 | true | ✗ 答错 | 已看工具 | 53674 |
| no_reasoning | 2 | 3 | true | ✗ 答错 | 已看工具 | 106798 |
| no_tool_calls | 1 | 0 | true | ⚠ 编造数字 | UNSUPPORTED | 60301 |
| no_tool_results | 5 | 4 | true | ⚠ 编造数字 | UNSUPPORTED | 120685 |

## 各模式分析

### 1. full（完整模式）→ ✓ 答对

- **迭代次数：5**，**工具调用：4**，**耗时：76280ms**
- 拥有全部能力，正确调用计算器和汇率工具完成多步计算，并给出结构化答案（同比增速 / Q2 折人民币 / 总营收）。
- **结局为 ✓ 答对**：答案通过 rubric 判定（增速 25%，Q2 与总营收与观察中的汇率一致）。
- 作为基线，代表 Agent 的完整性能表现。

### 2. no_history（移除历史记录）→ ✗ 答错

- **迭代次数：2**，**工具调用：1**，**耗时：53674ms**
- 每轮只发送 System + 最新用户消息，Agent 无法记住前几轮的上下文。
- 结果：Agent 返回通用性的自我介绍和功能说明，而不是针对任务的数值分析。
- **结局为 ✗ 答错**：模型看到工具（数字依据=已看工具），但答案不满足数值规则——**缺少历史导致任务无法推进。**

### 3. no_reasoning（移除推理）→ ✗ 答错

- **迭代次数：2**，**工具调用：3**，**耗时：106798ms**
- 禁止 `<thought>` 思考过程，直接调用工具。
- 结果：虽然调用了 3 次工具，但推理被抑制后分析逻辑与结论完整性下降，数值规则不通过 → **✗ 答错**。

### 4. no_tool_calls（移除工具调用）→ ⚠ 编造数字

- **迭代次数：1**，**工具调用：0**，**耗时：60301ms**
- 不向模型传入 tools，Agent 无法调用任何工具。
- 结果：模型"心算"并输出了一段工具调用描述（JSON），但没有任何计算依据。
- **结局为 ⚠ 编造数字**：数字依据=UNSUPPORTED——答案数字既不在任务文本里，也没有工具观察支撑。**数值计算能力完全丧失。**

### 5. no_tool_results（移除工具结果）→ ⚠ 编造数字

- **迭代次数：5**，**工具调用：4**，**耗时：120685ms**
- Agent 可以调用工具，但看不到返回结果（被隐藏），只能猜测。
- 结果：反复调用工具却得不到反馈，陷入"猜-试"循环（5 轮 / 4 次调用 / 120s），耗时最长。
- **结局为 ⚠ 编造数字**：模型看到的观察为空，答案数字无来源。**缺乏工具结果反馈会显著降低效率与准确性。**

## 结论

| 维度 | 影响 |
| --- | --- |
| 历史记录（history） | 移除后任务无法正确推进，Agent 退化为通用问答，是完成任务的核心前提 |
| 工具调用（tool calls） | 移除后彻底丧失数值计算与汇率转换能力，输出无据数字 |
| 工具结果（tool results） | 移除后 Agent 无法确认计算结果，陷入低效的猜测循环，耗时剧增 |
| 推理（reasoning） | 移除后分析逻辑与结论完整性下降，数值规则不通过 |

**总体：完整模式（full）是唯一"答对"的模式。历史记录与工具反馈是财务分析类任务最重要的能力，移除任一项都会导致任务无法正确完成；而"没有工具/看不到结果"会直接产出无依据的编造数字——这也是结果判定把"答对"和"数字有据"分开的原因。**

## 附：交互模式示例记录

交互模式（`sample <n>` 内置任务）的运行结果，用于展示 `parse_pdf` 与多工具协作。

### sample 2：PDF 财务分析

输入任务：`Analyze this PDF document: fixtures/pdfs/simple_expense_report.pdf`

**执行指标：** 迭代 2 次，工具调用 1 次，终止回复完成 true。

**Agent 回答摘要：**
成功解析 PDF 并提取关键财务数据：

- 报告周期：Q1 2024
- 各地区费用：美国 `$2,500,000` / 英国 `£1,800,000` / 日本 `¥380,000,000` / 欧盟 `€2,100,000` / 新加坡 `S$3,200,000`
- 全球员工总数：1,250 人
- Q2 目标：所有地区削减 8% 费用

Agent 还主动给出了后续可做的分析建议（统一折算 USD、占比、人均费用等）。

### sample 3：复杂财务分析

输入任务：多币种季度营收（Q1 USD / Q2 EUR / Q3 GBP / Q4 JPY），要求折算 USD、算总额、均值、最高季度、20% 利润率下的年度利润。

**Agent 回答摘要（关键数值）：**

| 年度总营收 | $9,742,640.50 |

演示了 Agent 连续调用 5 次工具（多次汇率换算 + 计算器）完成多步财务分析的能力。
