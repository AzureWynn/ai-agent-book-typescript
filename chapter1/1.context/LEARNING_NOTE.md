# Chapter 1-1：上下文感知 Agent 与消融实验 · 学习笔记（大白话版）

## 一、这个实验在干什么？

一句话：**做一个"会调用工具的财务分析 Agent"，然后用消融实验（Ablation Study）逐个拆掉它的能力，看哪块能力最重要。**

场景：让 Agent 分析一份 PDF 财报（同比增速、Q2 折人民币、总营收），它需要"读 PDF + 算汇率 + 心算"，完成这活儿靠四类上下文能力配合。

## 二、为什么需要消融实验？

```
完整 Agent（full）：历史 + 推理 + 工具调用 + 工具结果 全开 → 能完成任务

消融 = 把能力一个个拆掉，看哪个拆了之后效果掉得最狠：
  no_history      → 拆掉"历史记录"
  no_reasoning    → 拆掉"思考过程"
  no_tool_calls   → 拆掉"工具调用"（模型只能心算）
  no_tool_results → 拆掉"工具结果"（工具跑了，结果对模型隐藏）
```

**大白话：像做对照实验一样，每次撤掉一个变量，看结果差多少——就能定位"Agent 的能力上限由谁决定"。**

## 三、核心循环：思考-行动-观察（ReAct）

```
循环直到 maxIterations（10 次）:
  1. 思考：把「历史 + 系统提示词」发给 LLM
  2. 行动：若返回 tool_calls → 执行对应工具 → 结果塞回历史
  3. 观察：带着新观察继续下一轮，直到模型不再调工具 → 给出最终答案
```

4 个工具：

| 工具 | 用途 | 说明 |
|---|---|---|
| `calculator` | 数学计算 | 基于 mathjs，禁止模型心算 |
| `convert_currency` | 汇率换算 | 真实免费 API；失败时用备用汇率 7.2 |
| `parse_pdf` | 读本地 PDF | 返回前 2000 字符，防上下文爆炸 |
| `code_interpreter` | 执行 JS 代码 | `node:vm` 隔离沙箱，防逃逸 |

## 四、消融的 4 个开关 × 5 种模式

| 模式 | withHistory | withReasoning | withToolCalls | withToolResults | 意味着 |
|---|---|---|---|---|---|
| `full` | ✅ | ✅ | ✅ | ✅ | 完整能力（基线） |
| `no_history` | ❌ | ✅ | ✅ | ✅ | 每轮只发"系统 + 最新用户消息"，忘记历史 |
| `no_reasoning` | ✅ | ❌ | ✅ | ✅ | 禁止 `<thought>` 思考过程 |
| `no_tool_calls` | ✅ | ✅ | ❌ | ✅ | 不绑工具，模型只能"心算" |
| `no_tool_results` | ✅ | ✅ | ✅ | ❌ | 工具执行了，但结果对模型隐藏 |

## 五、结果怎么判定（本实验最重要的一课）

**"完成" ≠ "答对"**。单次结果用 3 个独立维度描述：

1. **completed（完成）**：只是"模型给了一段最终回答"，不代表答对。`no_tool_calls` 模式第一轮就必然回复，所以它"完成"但没答对。
2. **groundingVerdict（数字依据）**：答案里的大额数字，是否出现在"任务文本"或"模型真正看到的工具结果"里。`no_tool_results` 的答案数字没有来源 → `ungrounded`（编造）。
3. **taskSuccess（数值规则 rubric）**：是否满足任务专属的答案判定。对财务任务，从工具观察里**动态提取实际汇率**，计算期望值再比对。

> 为什么 rubric 不硬编码期望值？因为汇率是**实时 API** 返回的（可能不是 7.2）。硬编码会导致真实汇率下"算对的答案被判错"。所以期望值从观察里现算。

```
判定流程：
  有最终答案? ──否──→ 结局: 无终止回复
      │是
  答案数字有来源? ──否──→ 结局: 编造数字
      │是
  通过数值 rubric? ──是──→ 结局: 答对
      │否
      结局: 答错
```

## 六、实测结论（示例 ablation-results.md）

消融实验揭示的规律（供对照）：

- **no_tool_calls**：模型第一轮就直接心算回复，"完成"但数字没依据（编造）——证明工具调用对数值任务不可缺。
- **no_tool_results**：工具执行了但结果隐藏，模型照样编数字——证明"看到工具结果"才是 grounding 的来源。
- **no_history**：每轮忘记上下文，多步任务链条断裂。
- **no_reasoning**：禁止思考过程，复杂推理退化。

> 注意：官方实验记录特别提醒——一次五组对照**不一定观察到"去掉推理内容必然退化"**，不要把预期现象当作每次都能复现的结论。消融的结论要看统计规律，不是单次输出。

## 七、与之前/之后实验的联系

| 实验 | 关联 |
|---|---|
| 1-0 function-calling | 本实验是 1-0 手写协议的框架版（LangChain 封装版） |
| 1-2 web-search-agent | ReAct 循环几乎一样，只是工具从"确定性工具"换成"搜索" |
| 2-4 prompt-engineering | 同样是消融/对照思路，扩展到提示词的三轴消融 |

## 八、核心结论

1. **ReAct 循环（思考-行动-观察）是 Agent 的地基**，后续所有实验都是它的变体
2. **"完成" ≠ "答对"**：必须有独立的数字依据（grounding）和任务规则（rubric）双重校验
3. **工具结果必须真正喂回模型**：隐藏结果 = 逼模型编造
4. **rubric 的期望值要从观察里现算**，不能硬编码（实时数据会变）
5. **消融是理解 Agent 能力来源的通用方法**：拆一个能力，看一个效果
