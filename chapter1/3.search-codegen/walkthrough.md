# 深度解析：AI Agent 的“托管工具”协议是如何工作的？

在 AI Agent（智能体）的开发中，我们经常会遇到两种截然不同的工具调用模式：传统的**函数调用（Function-Calling）****和新一代的****托管工具（Hosted Tools）**。

如果你运行过类似 `npm run walkthrough` 的演示脚本，你会直观地看到这两者的巨大差异。本文将结合具体的执行流程，带你一步步拆解“托管工具”的底层协议与运行机制。

---

## 一、 核心概念：什么是“托管工具”？

简单来说，**托管工具就是由大模型厂商在云端提供并代为执行的平台级能力。**

- **传统模式（Function-Calling）**：模型只负责“思考”和“下达指令”，你的本地代码负责“执行”（比如你自己写代码去调搜索引擎 API）。
- **托管模式（Hosted Tools）**：模型不仅负责思考，连“执行”这一步也交给了云端。模型生成的不再是简单的 JSON 参数，而是直接在厂商提供的安全沙箱环境中自动运行代码或执行搜索。

---

## 二、 逐步拆解：托管工具的 7 步运行流

通过以下 7 个步骤，我们可以清晰地看到托管工具是如何在“黑盒”中完成工作的。

### 步骤 1：请求声明（只声明类型，不提供逻辑）

在发起请求时，我们在 `tools` 参数中声明了 `web_search` 和 `code_interpreter`。

- **关键点**：这和传统的 Function-Calling 在形式上看起来一样，但**本质不同**。你并没有提供这些工具的执行代码，只是在告诉模型：“这两个是平台级的能力，你可以随时调用。”

### 步骤 2：模型“心想”要用工具

模型接收到你的问题后，分析认为需要先上网搜索信息，于是生成了一个使用 `web_search` 工具的“意图”。

- **关键区别**：在传统模式下，模型会返回一个 `tool_calls` 请求，你的程序必须捕获它并自己去执行搜索。而在托管模式下，模型只是“心想”一下，它知道这个工具不由你执行，所以不会生成让你去执行的请求。

### 步骤 3：托管层执行（云端黑盒）

你的 Agent 程序（或 SDK）识别到模型想使用 `web_search` 后，将这个意图转发给**托管层**（如 OpenAI 或 DashScope 的服务器）。

- **黑盒操作**：云端的托管层接收到指令，在自己的服务器上执行真实的网络搜索，抓取网页，并整理结果。这个过程对你来说是完全透明的。

### 步骤 4：生成“已完成”的记录

这是托管协议最核心的特征。托管层执行完毕后，会生成一个 `web_search_call` 类型的记录，并把它作为对话历史的一部分返回。

- **关键点**：注意，这个记录的 `status` 是 `completed`（已完成）。它不是一个“请求”，而是一个 **“执行报告”** 。这个报告里包含了精确的来源链接（`citations`）和整理好的搜索摘要（`result`），供模型在下一轮对话中使用。

### 步骤 5：模型继续思考，调用下一个工具

模型收到了上一步的搜索结果，现在它需要计算哪两个首都距离最近。于是，它再次“心想”要用 `code_interpreter`。

- **再次托管**：和搜索一样，这个计算请求也被发送到托管层。托管层在一个安全的沙箱环境（如 `node:vm`）里执行模型生成的代码。

### 步骤 6：生成代码执行记录

计算完成后，托管层生成一个 `code_interpreter_call` 记录，`status` 同样是 `completed`，并附上代码（`code`）和输出结果（`output`）。

### 步骤 7：组装完整响应并提取答案

整个流程结束后，API 返回给你的不是一个简单的文本答案，而是一个包含所有步骤的“完整响应对象”（`response.output`）。

- **内容**：这个对象是一个列表，按顺序包含了：
    1. 一个 `web_search_call` 记录
    2. 一个 `code_interpreter_call` 记录
    3. 一个 `message` 记录（包含最终给用户的文本回答）
- **价值**：你的程序可以精确地遍历这个列表，知道模型具体做了什么、引用了哪些来源、执行了什么代码。这就是“可验证性”。

---

## 三、 总结：两种模式的本质差异

通过上述流程，我们可以清晰地对比两种模式：

| 特性 | 传统函数调用 (Function-Calling) | 托管工具 (Hosted Tools) |
| ------ |------ |------ |
| **模型输出** | `tool_calls`（一个**请求**） | `tool_call` 记录（一个**已完成**的报告） |
| **执行方** | **你的代码** | **厂商的托管层**（云端黑盒） |
| **你的角色** | 必须实现工具逻辑，捕获请求并执行 | 只需声明工具，无需关心执行细节 |
| **核心优势** | 灵活，可调用任何自定义业务工具 | 安全、高效、开箱即用、结果可验证 |

**一句话总结：**

- **函数调用**是模型给你下“工单”，你得自己去干活。
- **托管工具**是模型告诉平台“我要用某个能力”，平台干完活后，把“工作报告”发给你和模型看。

在实际开发中，这两者通常是配合使用的：**通用能力用托管**（如搜索、算数、画图表），**私有业务用自定义**（如查询内部数据库、操作自有业务系统）。
