# 2.output-resume 教学笔记：续写省不省，看模型听不听话

官方 5-2 的本地版：流式 120 字掐断，三策略恢复。断点只做 text 与 tool_args——本地模型无独立思考通道，reasoning 记 N/A（官方 prefill 在此本就退化整轮重发，如实声明不硬凑）。

## 一、本地结论和官方是反的，但都是真的

官方（线上大模型）：正文断点 prefill 省 15%~66% 输出 token。
本地（gemma4，temp 0）：prefill 反而多花 21%，meta 多花 31%；JSON 臂更夸张，多花一倍以上。

原因不在 harness，在模型行为：大模型收到前缀会"接着写"，小模型收到前缀会"连前缀带后文重讲一遍"（续写里经常把半截内容改写复述）。**省 token 的前提是模型真的只写后半截**——约束（hint）写了，模型不听，省就是负的。这是个模型能力结论，不是 harness bug。

## 二、恢复成功率 12/12，但"恢复"不等于"省"

三策略全部恢复成功（text 含 3/3 天，JSON 合法且值对）。所以决策表是：
- 要省：整轮重发（本地小模型上最便宜，且无拼接风险）。
- 要快（首字快、少等）：prefill 照样有价值——用户 120 字不用等整轮，只是总 token 多。
- meta 最贵：既看不见前缀（纯靠描述定位断点），又容易复述，本地垫底。

## 三、JSON 臂验证了"合法≠正确"要分开记

本实验 JSON 短、hint 强，合法率正确率都是 6/6。但门禁照官方拆成两列：`JSON.parse` 过不过（合法），四字段和参考值一不一样（正确）。拼接处多空格、值被改写（如把 150000 写成"15万"）只挂第二列——分类账记清楚，爆雷时才知道哪段坏了。

## 四、token 用 eval_count，不用字符除四

Ollama 每次返回真实 `eval_count`，resend 当基准算节省率。temp 0 下 repeats 两轮数字完全一致——确定性模型的重复就是复读，repeats 的意义从"测方差"变成"验稳定"，如实写进结论。

## 实测（gemma4，Ollama 本地，断点 120 字）

- text：resend 580（基准）/ prefill 702（-21%）/ meta 760（-31%），恢复 6/6
- tool_args：resend 183（基准）/ prefill 410（-124%）/ meta 399（-118%），合法正确 6/6
