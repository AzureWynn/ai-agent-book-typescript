# 1.trajectory-handoff 教学笔记：切换时带什么，不带什么

官方 5-1 的本地版：A（Ollama chat 接口形状）跑 2 个工具 → 人为 429 → 切 B（generate 形状）三臂接管。先声明降级点：**两家底下是同一个模型**，测的是格式搬运与进展保留，不是真实厂商互斥。

## 一、strip 的浪费是真浪费，direct 的通过是假通过

- strip：数据齐、总额对，但重复调用 2 个、4 轮、1342 token——从头再来，该交的学费一分没少。
- direct：0 重复一次过。但别鼓掌：直传在官方六组真厂商对里三度被拒（凭证/结构不认），本地通过只因底下是同一模型、看得懂自家杂质。**direct 的 ✓ 是实验设计的假阴性，不是方案的胜利**，README 对照表里照实标。
- neutral：0 重复、2 轮、总额对。唯一在"真厂商对"和"本地降级"下都成立的臂。

## 二、中立格式的三样东西，本地只剩两样半

官方：思考拆文字/凭证、调用记名+参数、结果重渲染。本地 Ollama 无签名机制，credential 恒 null——但双槽结构保留，代码里看得见"本该丢什么"。带走的是文字叙事 + 已知结果清单 + "不许重做"禁令，这三句就是 neutral 臂 0 重复的全部原因。

## 三、"```tool JSON块"事件：模型照抄提示词里的 prose

首版 SYSTEM 写"用 ```tool JSON 块"，模型第一轮回了个 fence 标签叫 `tool JSON块`——把说明文字当成了标签名。修法：few-shot 逐字示范 + 解析器容忍任意 fence 标签（以 JSON.parse 为准）。0.coding-agent 的教训在这里又交了一次学费：**凡是没给逐字示范的格式，小模型必按字面理解跑偏**。

## 四、熔断计数别绑模型调用次数

首版"第 3 次调 A 就 429"：一次格式错误浪费掉调用，熔断提前误伤，切换前就崩。改成"2 次工具调用完成才 trip"——**熔断绑的是业务进展，不是请求次数**。官方的 SWITCH_AFTER 也是这个语义。

## 实测（gemma4，Ollama 本地，chat→generate，2 工具后切换）

- direct：首请求200，数据齐✓，总额对✓，重复0，2轮/871token（假通过，见上）
- strip：首请求200，数据齐✓，总额对✓，重复2，4轮/1342token
- neutral：首请求200，数据齐✓，总额对✓，重复0，2轮/933token
- 总额标准答案 10600，三臂全对（总额正确性不受接管质量影响，官方亦单列）
