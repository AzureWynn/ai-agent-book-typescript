# Chapter 5-4：逻辑谜题约束求解 · 学习笔记（大白话版）

## 一、这个实验在干什么？

一句话：**别用脑子算逻辑，用代码算——把谜题翻译成程序，让机器穷举。**

```
骑士永远说真话，无赖永远说假话。
A 说："我们两个都是无赖。"
问：A 和 B 各是什么？

人算：A 若是骑士→话为真→A 是无赖→矛盾；所以 A 是无赖→话为假→B 是骑士。
      两步还行，五个人就数不过来了。

机器算：X == (X 那句话的真值)，2^5=32 种组合全试一遍，0.01 秒。
```

三模式对照：纯思考（直接答）、代码辅助（写约束程序再跑）、离线求解器（标准答案怎么来的）。

## 二、核心规则只有一条

**双条件约束**：`X 是骑士 ⟺ X 说的话为真`，即代码里的 `X == 真值`。

```
A 说"B 是骑士"  →  A == B
B 说"C 是无赖"  →  B == (not C)
"恰好有两个骑士" → sum(...) == 2
"至少两个"      → sum(...) >= 2
```

每句话独立翻译，翻译完就没模型什么事了——剩下的全是确定性穷举。这就是"外包"的含义：**容易错的那部分（真值传播）交给不会错的部分（程序）**。

## 三、谜题集是怎么保证的？

手写 8 题（2人×2、3人×4、4人×2、5人×1），每题用求解器验两件事：

```
1. 解数 == 1（多解的题不能要，如 kk09 草稿版有 2 个解，已删）
2. 解 == 标答（手算标了 8 题，错了 3 个——别信手算）
```

第二条是本实验最诚实的注脚：**连出题人手算都错 3/8**，凭什么指望模型心算全对？

## 四、解析器也曾经冤枉过模型

`npm run eval` 第一版跑出 pure 12.5% —— 后来发现 parser 取的是**首次出现**，而模型习惯先列假设再下结论，抓到的是中间假设。改取**最后一次出现**（结论区）后重跑。教训：

```
评测链：模型输出 → 解析 → 判分
解析错了，判分全错——先审 parser，再骂模型
```

最终成绩以重跑版为准（见 README 实测结果）。

## 五、试金石：模型会写代码吗？

开工前测过：FizzBuzz 一遍过；1~1000 中 3 和 7 公倍数之和 = 23688，一遍过。结论：gemma4 写简单代码可靠——约束程序这种"模板化代码"在它能力圈内，实验才值得做。如果试金石挂了，就该降题而不是硬跑。

## 六、本实验怎么跑

```bash
npm run solver    # 离线基线：8 题全解（无需 Ollama，先跑这个）
npm run demo      # kk01 单题三模式追踪（需 Ollama）
npm run eval      # pure vs code 对照表（需 Ollama，约 15～20 分钟）
npx tsx src/main.ts --mode eval --limit 4            # 省钱冒烟：前 4 题
npx tsx src/main.ts --mode eval --max-people 3       # 只跑 ≤3 人
```

## 八、关键洞察

1. **双条件是全部**——`X == 真值`，一条规则覆盖所有题型（含计数）
2. **出题要靠求解器验**——唯一解 + 标答一致，缺一不可
3. **先审 parser 再骂模型**——解析取首次还是末次，能差出几十个百分点
4. **试金石先行**——模型写代码行不行，两道题就知道
5. **弱模型增益最大**——官方刻意用 gpt-4o-mini；强模型纯思考也能解，增益归零

## 九、官方对照与诚实声明

官方 12 题 gpt-4o-mini：pure 50% vs code 100%（+50pp）；官方 84 题正式活动：code 39.3% vs pure 75.0%——**方向反了**，完整负结论保留。两个教训：

```
1. 小样本对照 ≠ 大规模结论（12 题 vs 84 题能讲出相反故事）
2. 翻译质量决定一切：solver 100% 只证明"翻对了就行"，模型翻不对就没分
```

本实验 8 题 + gemma4 的数字见 README，只代表"这个模型、这组题"。

## 十、常见问题

- **代码跑不起来**：先看模型生成的代码原文（eval 暂不存，demo 打印）；八成是 import 或缩进问题
- **答案解析失败**：模型用了 parser 没见过的格式（如表格）；放宽正则或要求固定格式
- **想加题**：照 types.ts 的 7 种陈述类型写 stem + statements，跑 solver 验唯一解后再入库
- **python-constraint 呢**：官方用的库；本实验题小（≤32 组合），itertools 穷举等价且零依赖
