# Chapter 5 汇总笔记：Coding Agent 与代码生成（章级）

> 对应《AI Agent 开发实战》第 5 章。本章核心：**代码是「能创造新工具的工具」——生成代码只是开始，结果仍需与任务要求核对。**

## 一、本章一句话

**Coding Agent 的价值不在"会写代码"，而在把读、改、跑、验四个动作串成闭环——把推理、计算、约束、校验尽量外包给确定性执行，让模型只做它擅长的事（写意图），机器做它可靠的事（跑结果）。**

## 三、贯穿全章的主线：编码循环 + 外包确定性

官方正文把 Coding Agent 总结为一个循环，后面每个实验都是它的一段：

```
读/搜 → 补丁 → 测试 → 修复 → 验证
```

本章所有实验都在回答同一类问题：**循环里哪一步该交给模型，哪一步该交给机器？**

```
外包给确定性执行（机器）
├── 5-3 计算：模型写程序 → 沙箱跑 → 结果为准
├── 5-4 逻辑：模型写约束 → 求解器穷举 → 答案为准
├── 5-5 校验：模型自报 → 服务端真值对账（最后的锁）
├── 5-10 回归：新 parse() → 必需字段断言 → 过才入库
├── 5-12 表单：生成 HTML → jsdom 真执行 → 结果回交
├── 5-13 SQL：模型产 SQL → 数据库执行 → 对参考实现
└── 5-14 UI：整文件改写 → 内容断言 + vite build 通过

留给模型（会出错也要外包不了的）
└── 5-1 叙事与进展保留：切换时带叙事不带格式
```

**核心思想：让模型写"意图"，让机器跑"结果"，验收永远看机器怎么说，不看模型怎么说。**

## 四、核心知识点提炼

### 1. 最小 Coding Agent（Starter）：先有循环，再有智能

- 小模型第一反应是"写教程"不是"动手"——它把自己当聊天助手。修法两行：**few-shot 首轮逐字示范** + **"你有手"禁令**（用户只看 FINAL）
- 工具语义要覆盖模型的自然写法（`dir/**`）；**"无结果"是最危险的返回**，模型会把它当事实
- SystemState 三件套：状态栏每轮注入（KV Cache 友好）/ 格式错误回灌（解析失败喂"错在哪+原文"）/ 重复指纹熔断（防无限循环）
- 完成标准 = "测试通过"，不是"代码写完"；eval 破坏性，幂等靠 `resetFixtures()`

### 2. 5-1 跨厂商轨迹接管：切换时带叙事，不带格式

- 三臂：direct（原样搬运）/ strip（剥离思考从头再来）/ neutral（中立格式）
- **strip 的浪费是真浪费**（重复调用、多轮多 token）；**direct 的通过是假通过**（同模型看得懂自家杂质，真厂商对里被拒）
- 中立轨迹 = 思考拆文字/凭证双槽 + 调用记名+参数 + 结果重渲染——**轨迹不该按任何一家接口格式存**，重放/训练/复盘才能通用
- 熔断计数绑**业务进展**（2 次工具调用完成），不绑模型请求次数

### 3. 5-2 流式中断接续

- 思考/正文/参数三处切断，text 臂看恢复 + 省 token；json 臂看**合法 ≠ 正确**（参数断点会拼出"合法但写错"的参数）
- 小模型续写会复述已说内容——**省 token 是模型行为红利，不是协议保证**

### 4. 5-3 / 5-4：外包计算与逻辑

- 代码臂 vs 纯思考：计算题（AIME）53.3% vs 36.7%；逻辑题 39.3% vs 75.0%——**外包的是执行，不是理解**
- 建模错了程序照样错（m02 误用费马定理）——模型仍要为"写什么程序"负责
- 双条件约束 `X == (X 那句话的真值)`：一条规则管全部；穷举 2^n 组合机器不会漏

### 5. 5-5 小模型代码化规则

- control（自然语言政策）vs codified（政策 + checklist + 自报 + **服务端真值校验**）
- 拦得住钱，拦不住嘴（模型说"已完成"不算数，服务端对账才算）
- 诚实负结论：本地 60×2 配对未显著提升（91.7% vs 95.0%）——如实保留

### 6. 5-10 自适应日志解析：测试是进化的锁

- 新日志格式 → 解析失败 → Agent 生成 `parse()` → **必需字段断言自动测试** → 通过才热更新 → 持久化复用
- 没有客观验收，生成什么都敢入库；热更新管本次，持久化管重启，分开验证

### 7. 5-12 / 5-13 / 5-14：可见产物的验收

- 动态表单：级联逻辑（联动下拉/依赖校验）**静态校验不够，必须 jsdom 真执行**，一次提交胜追问
- ERP：artifact 模式让 LLM 只生成 SQL 制品不搬运数据，省 token 又防错，参考实现验分
- 对话式 UI：改白名单源码 → 内容断言（新值出现 + 旧值消失）→ vite build 通过即生效

### 8. 5-16 Agent 造 Agent

- 双臂：从零（全文件自写）vs 模板（reference 全文 + 改）；**模板省协议**，门禁按成本排序（文件/密钥/编译/步数/测试/真跑）
- 过门多者胜，同分比 token；诚实负结果：模板质量非劣但"严格占优"未出现

## 五、工程实践启示

1. **约束优先于指导**：few-shot 逐字示范 > 讲规则；"按协议输出"是指导，"照抄这个"是约束
2. **能外包就外包**：计算/逻辑/校验/回归测试/构建，全部交给确定性执行，模型只写意图
3. **验收永远看机器**：服务端真值、沙箱输出、断言通过、build 通过——模型自述"已完成"不算数
4. **诚实记录负结果**：5-3/5-4/5-5/5-16 都有正式负结论，如实保留比美化更有价值
5. **熔断绑业务进展**：重试/熔断/切换的闸门绑任务完成度，不绑调用次数
6. **设计可重放的中立格式**：轨迹存中立不存厂商格式，切厂商/复盘/训练一份通吃
