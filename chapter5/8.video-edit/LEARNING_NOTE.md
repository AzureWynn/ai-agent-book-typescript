# 8.video-edit 教学笔记：两步定位，一次审核

官方 5-8 本地版：ffmpeg 合成 4 场景测试片（色块+烧字，非实拍）→ Proposer 解析 → 两步 Vision 定位 → ffmpeg 剪辑 → Reviewer 抽帧审核迭代。

## 一、环境缺什么就绕什么，但绕路要留收据

本机 ffmpeg 无 drawtext/libass：标签字改 PIL 烧字 + overlay，字幕改 srt 旁路（不烧录）。两处降级都在代码注释和 README 里写明。**环境适配 Cristina 属于 harness 工作，但适配点必须可审计**——后人看到 srt 就知道"这里本该有个烧录步骤"。

## 二、粗定位看字，细定位数字数

粗粒度 4 帧一次问出 index（SURFING 在第 2 张），细粒度窗内 10 帧一次问 from/to。两次定位误差 0/0s。合成素材字大清楚，这是"开卷考"——如实声明：结论限"循环跑得通"，Vision 在真实杂乱画面上的能力另测（那是 5-6 的活）。

## 三、Reviewer 第一轮就过，迭代逻辑没练到

两需求都 1 轮通过。审核闭环的 revise_bounds 写了但没触发——覆盖率有缺。诚实记一笔：迭代路径未经验证。补法是故意给错边界跑一次（留作练习），或者接受"审核通过"本身就是审核逻辑的验证。

## 四、子 Agent 隔离截图，主上下文不污染

定位用的 14 张截图只进 analyzer 的调用，不进主循环——官方"Token 统计分离"的本地对应。prompt 里每帧标时间顺序，小模型按图索骥不迷路。Vision 调用 3 次/需求（粗1+细1+审1），全走 Ollama 本地。

## 实测（gemma4 vision，Ollama 本地）

- 冲浪：定位 [10,20] 误差 0/0，1 轮通过，成片 10.0s
- 滑雪+Winter 字幕：定位 [20,30] 误差 0/0，1 轮通过，成片 10.0s + srt✓
