# 0.coding-agent 教学笔记：先有循环，再有智能

官方没给这个 Starter 编号，但它是第 5 章的地基：后面 5-3 到 5-16 每个实验，拆开都是"读/改/跑/验"循环里的一段。本实验把它最小化：七个工具 + 一个主循环 + 两个任务。

## 一、小模型的第一反应是"写教程"，不是"动手"

第一版跑 T1：12 轮全是格式错误，工具调用 0 次。模型回的是"两种解决方案…请把代码粘贴到文件里运行"——它把自己当聊天助手，把用户当执行者。

修法两行，立竿见影（12 错 → 0 错）：
1. **few-shot 首轮示范**：把第一轮该回什么逐字写出来，模型照抄就会了。讲规则不如给例子。
2. **"你有手"禁令**：不许给用户写教程让用户去跑，用户只看 FINAL。

这是 Harness 工程"约束优先于指导"的活例子：光说"按协议输出"是指导，给出逐字示范才是约束。

## 二、工具要按模型的真实用法补，不能怪模型

修好协议后模型调 `grep {"pattern":"TODO","glob":"sample-project/**"}`，harness 回"无匹配内容"——因为自研 glob 只懂 `**/*.ext`，不懂 `dir/**`。模型信了，写了个空清单还 FINAL 声称完成。

教训两条：
- 工具的匹配语义要覆盖模型的自然写法（补了 `dir/**` 和 `**`，T1 一次过）。
- "无结果"是最危险的返回：模型会把它当事实。更好的 harness 会在 0 命中时追一句"换个 pattern 试试？"——本实验没做，留作练习。

## 三、T2 走完了完整工程循环

T2（5 轮 4 调用）：bash 复现失败 → read 看源码 → edit 改运算符 → bash 跑测试 → FINAL。声称完成前用工具验证——"测试通过"而非"代码写完"才是完成标准，官方这句话在本实验里是可执行的。

## 四、官方 SystemState 三件套的本地版

- **状态栏每轮注入**：分支/未提交变更/最近提交放 `<system_hint>`，静态提示词不动（KV Cache 友好）。
- **格式错误回灌**：解析失败不崩，把"错在哪+上一轮原文前 500 字"喂回去，模型自纠。
- **重复指纹熔断**：同样调用连发两次就警告换策略，防第一章消融实验里的无限循环。

## 五、eval 是破坏性的，幂等靠 reset

T2 会真修掉 bug，不重置第二次跑就是开卷考。`resetFixtures()` 开头结尾各调一次，跑完 workspace 回到初始态——测试夹具的"可重复"和"真做事"不矛盾，靠重置调和。
