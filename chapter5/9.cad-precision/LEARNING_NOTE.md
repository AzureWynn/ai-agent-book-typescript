# 9.cad-precision 教学笔记：参数是锚，代码是船

官方 5-9 的 CAD 臂本地版：模型写 CadQuery 法兰盘 → 执行导出 → 测量 6 项 → M5→M6 单点修补 → 重测验零漂移。B臂（diffusion）本地无 HF Space，引用官方结论。

## 一、小模型不会 CadQuery：骨架是唯一的桥

裸 prompt 下模型三连挂：`union(*sketches)` 无 solid、`cq.WorkPoint` 不存在、`base.cut(workplane)` 类型错——全是 API 幻觉。stderr 回灌修不好：每次换一种错法，3 次打完。

修法是 5-16 的"模板省协议"：prompt 里直接给 8 行标准骨架（PARAMS + extrude + faces(">Z").pushPoints.hole），模型只填值。第一次尝试 6/6 全过。**弱模型 + 生僻 API = 必须给骨架**，这不是作弊，是把"考 API 记忆"和"考参数化思想"分开——本实验要的是后者。

## 二、测量才是"代码即真相"的闭环

包围盒量外径/厚度/底面，圆柱面数孔、量孔径、算孔位圆——6 项全是几何真值，不听模型自称。M5 6/6、M6 6/6、漂移 4 项全 0.000。对比 5-14 的 vite build、5-4 的 solver：**每个"代码当裁判"的实验都要有一个独立测量器**，裁判和运动员不能是同一段代码。

## 三、变更成本 1 行 0 调用：参数化的全部论点

M5→M6：正则改 PARAMS.hole_diameter 一处，重跑，无 LLM。官方 B臂：整体重跑 + 外径漂移 +283%。这组对照的教学点与绿植对照组（官方：自然度 3 vs 8 反转）合在一起才是完整的：**精度任务代码赢，审美任务生成赢，`(5-9)` 的标题"适用边界"指的就是这条线**。本地只跑了精度半边，审美半边引用官方。

## 实测（gemma4 写码 + CadQuery 2.8 本地执行）

- M5：6/6（骨架版 1 次建成；裸 prompt 版 3 次修不好）
- 修补：1 行，0 LLM 调用
- M6：6/6；外径/厚度/孔数/孔位圆漂移全 0
