# Chapter 5-3：代码辅助数学 · 学习笔记（大白话版）

## 一、这个实验在干什么？

一句话：**心算会错，代码不会——把算的部分外包给 Python。**

```
2^1000 的各位数字之和 = ？
人算：302 位数字，一个一个加？没门。
代码：sum(map(int, str(2**1000))) → 1366，0.01 秒。
```

两模式对照：纯 CoT（只许想，不许写代码）vs 代码辅助（写程序跑出数再答）。模型、题目完全相同，差的只是"许不许用计算器"。

## 二、题库怎么保证是对的？

8 道题，每题三样东西：题面、整数标答、参考解程序。入库前 `npm run selfcheck` 全跑一遍：

```
m01  真值=23688  沙箱输出=23688  ✓
...
m08  真值=1366   沙箱输出=1366   ✓
参考解命中真值：8/8
```

标答不是手算的，是参考解跑出来的——手算 8 题这种事，3-12 已经证明人类不擅长。

## 三、答案格式为什么这么死？

判分只认一行：`FINAL ANSWER: <整数>`，取不到再退到"最终答案是 X"、最后退到"最后一个整数"。

```
宽松是陷阱也是救生索：模型爱写"**FINAL ANSWER**: 1366"（markdown 加粗）、
"最终答案是 1366"——判分 parser 必须全吃，否则"答对了也算错"。
但 code 模式有一次全体"?"：模型跑对了代码却死活不报数。
修法：code 模式先看模型报数，报不出就取最后一次成功执行的 stdout 末尾整数——
程序的输出就是答案，模型报不出来是格式问题，不是计算问题。
如果模型明确报了另一个数（如复核走火入魔），以模型说的为准（那是真错）。
```

## 四、模型会自己推翻正确答案

实测名场面（m08）：第一轮跑出 1366 是对的，模型不放心，又写了个 `pow(2, 1000, 9)` 去"验证"，拿到 7（数字根），然后晕了。

修法（脚手架，不是作弊）：system prompt 加一句"第一次执行成功得到数字后，直接用该数字作答，不要再写验证代码"。**什么时候停**也是 harness 设计的一部分，和"什么时候调工具"同等重要。

## 五、官方结论是什么？

```
gpt-4o-mini：纯 CoT 6/11 vs 代码 8/11（+2 题）
gpt-5.6-luna：纯 CoT 10/11 vs 代码 11/11（+1 题，只剩最难的枚举题）
正式 30 题：53.3% vs 36.7%，p=0.125 —— 没过显著性，不宣称胜利
```

三句话：
1. 代码辅助 ≥ 纯 CoT，方向稳定（弱模型差距大，强模型差距小）
2. 小样本表格是教学示例，不是正式结论（30 题都不显著，8/11 题更别吹）
3. 模型↔脚手架此消彼长：5-4 的 gemma4 纯思考全解增益归零，这里看 gemma4 能不能被难住

## 六、本实验怎么跑

```bash
npm run selfcheck   # 参考解跑沙箱对真值（无需 Ollama，先跑这个）
npm run demo        # m08 单题双模式追踪（需 Ollama）
npm run eval        # 8 题对照表（需 Ollama，约 15～20 分钟）
```

## 八、关键洞察

1. **外包的是计算，不是理解**——建模错了，跑出来的数再精确也没用
2. **停机规则是设计**——"拿到数字就停"和"调什么工具"同等重要
3. **判分 parser 先审**——5-4 的冤案在这里差点重演（格式严→改宽松）
4. **题库真值链**——参考解跑沙箱，标答=程序输出，不出手算
5. **小样本别吹结论**——8 题只能看方向，显著性交给大样本

## 九、常见问题

- **模型不调工具直接答**：code 模式 system prompt 已约束；偶发徒手答按失败计（它选的）
- **FINAL ANSWER 解析失败**：先看原文，很可能是格式变体；放宽正则
- **sympy 没有**：本实验题目只用 stdlib + math，numpy 现成；要 sympy 就 pip 装
- **想加题**：给 question/answer/reference，先 `selfcheck` 跑出真值再入库
